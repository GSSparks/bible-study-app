# frontend/src/components/AdminView.jsx

## Purpose

Admin control panel. Only rendered for users with `role === 'admin'`. Provides 7 tabs covering user management, module installation/visibility, content moderation, media management, system metrics, branding, and the AI overview cache (Codex).

## Props

| Prop | Type | Description |
|---|---|---|
| `auth` | object | `{ user }` — component guards itself; non-admins see nothing |

## State / key logic

**Tab system:** `activeTab` state selects among: `users`, `modules`, `posts`, `media`, `metrics`, `branding`, `codex`. Each tab is a self-contained sub-component.

**UsersTab:**
- Lists all users via `api.listUsers()`.
- Admin can create new accounts (username + password), change user roles (user/admin), and delete users.

**ModulesTab:**
- **Type filter:** BIBLE / COMMENTARY / DICT / BOOK buttons filter the displayed lists.
- **Repository browse + install:** `api.listRepoModules(type)` → paginated list of available SWORD modules. Install button calls `api.installModule(name)` (synchronous; large modules block).
- **Installed modules:** `api.listInstalledModules(type)`. Each row has:
  - **Visibility toggle** — `api.setModuleVisibility(name, visible)`. Hidden modules are not shown to regular users (AdminView still shows them).
  - **Remove** — `api.removeModule(name)`.
- **Manual .zip upload:** `FormData` POST to `/api/modules/upload`. Allows installing a pre-packaged SWORD module zip without repo access.

**PostsTab:**
- Lists all posts across the platform. Admin can delete any post or comment.

**MediaTab:**
- Lists uploaded PDFs. Admin can delete documents.

**MetricsTab:**
- Shows basic system metrics: user count, note count, session count, storage usage.

**BrandingTab:**
- Single field: app name. Saved via `api.updateAppSetting('brandName', value)`. Reflected globally via `AppShell`'s `brandName` state.

**CodexTab:**
- AI overview cache management. Lists cached passage overviews (generated by `GET /api/codex/overview`).
- **Export as .zip Markdown module:** `api.exportCodex()` → downloads a `.zip` file structured as a Markdown commentary module (`md:` prefix), ready to drop into `MD_MODULES_PATH`.
- Individual cache entries can be deleted.

## Dependencies

- `api` (`../api/client.js`) — numerous admin-specific endpoints.

## Notes

- Module installation is synchronous on the server; installing large SWORD modules (e.g. full Bible with Strong's markup) will block the HTTP request for several seconds (known limitation — no SSE/WebSocket progress).
- The Codex export zip format matches the Markdown module spec: `module.json` + per-book `.md` files with `## chapter:verse` headings.
- `ModuleVisibility` records are per-module; the toggle creates or updates a `ModuleVisibility` row in Prisma.
