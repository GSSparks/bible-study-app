# backend/src/db/prisma.js

**Purpose**

Creates and exports a single shared `PrismaClient` instance for the entire backend process. Centralising the client in one module ensures connection pooling works correctly and avoids the "too many clients" problem that arises when each service file independently instantiates its own client.

**Key exports / contents**

- `prisma` (named export) — a `PrismaClient` instance, default configuration (reads `DATABASE_URL` from the environment automatically).

**Dependencies / relationships**

- Imported by virtually every service file (`authService.js`, `noteService.js`, `swordService.js`, etc.) and by `middleware/auth.js` for session-attached user lookups.
- `PrismaClient` is imported from `@prisma/client`, which is generated by `npx prisma generate` from `backend/prisma/schema.prisma`.

**Notes**

The source comment acknowledges that `node --watch` (dev mode) can create duplicate client instances on file-reload. For a small self-hosted app this is acceptable; if it causes connection exhaustion in the future, stash the instance on `globalThis` using the pattern from the Prisma/Next.js docs. There is no explicit `prisma.$disconnect()` call — the process-exit handler is relied upon.
